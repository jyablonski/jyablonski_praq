Why does the forecast move?

The model learns the response

Each day, the model estimates the probability that a still-unsold seat sells. It multiplies that probability by the remaining inventory, adds expected sales, then repeats for the next day. Sales naturally accelerate near the game and stop at the 1,000-seat capacity.

The price and matchup multipliers refer to daily sale odds per unsold seat. They are not multipliers for total tickets sold; inventory and the time left limit the final effect.

What is actually being estimated?


          
This is a binomial logistic regression, fitted with NumPy using the count sold and the inventory at the start of each day. Coefficients are estimated from sales; the forecasting code never reads the generator's hidden demand parameters.

        

      

    


    

      
How much trust has it earned?

      

      

      

      

      
What this proves: the fitted model can recover useful relationships in this synthetic world and predict later synthetic games. Price plans were assigned independently of hidden demand before sales began, including 50% cuts. In real ticketing, slow games often get discounted and popular games get higher prices, so changing a price input alone does not establish its causal effect. Real deployment needs credible price experiments and evaluation on actual future games. The range is pooled across historical price plans, not validated separately for every scenario.

Run from the repository root. Dependencies: NumPy and pandas (also listed in this folder's requirements.txt). The report works directly from disk with no server or network requests. The default seed is 42; use --seed to generate another sample. CLI runs regenerate files in output/ unless --output-dir is supplied.
